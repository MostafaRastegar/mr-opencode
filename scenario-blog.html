سناریوی کامل ساخت پروژه بلاگ با mr-opencode

برنامه را به عنوان یک «واibcoder کامل» برای توسعه محصول اجرا می‌کنیم.

در این سناریو دولوپر هیچ کد پروژه را نمی‌نویسد؛ فقط به سوالات سامانه پاسخ می‌دهد.

نکته: تمام بخش‌های زیر به ترتیب اجرا می‌شوند. دولوپر در هر مرحله یک پاسخ کوتاه می‌دهد و سامانه به مرحله بعد می‌رود.
مرحله ۱: آماده‌سازی پروژه

دولوپر ابتدا پوشه پروژه را می‌سازد و فایل‌های تمپلیت mr-opencode را کپی می‌کند:

mkdir blog-project
cd blog-project
cp -r /path/to/mr-opencode/product/agents/. .opencode/agents/
cp -r /path/to/mr-opencode/product/commands/. .opencode/commands/
cp -r /path/to/mr-opencode/product/plugins/. .opencode/plugins/
cp -r /path/to/mr-opencode/product/skills/. .opencode/skills/
cp -r /path/to/mr-opencode/product/scripts/. .opencode/scripts/
cp /path/to/mr-opencode/product/configs/opencode.jsonc opencode.jsonc
cp -r /path/to/mr-opencode/product/AGENTS.md product/.githooks product/.env.example product/.gitignore .
git init
git config core.hooksPath .githooks

سامانه: فایل‌ها کپی شدند. گیت آماده است. حالا می‌توانیم Placeholderها را پر کنیم.

مرحله ۳: شروع کار با اورکستراتور
دولوپر: → opencode --agent orchestrator "run: plan-feature"
سامانه (اورکستراتور): سلام. من اورکستراتور این پروژه هستم. قبل از هر چیز، برنامه ورک‌فلو این ویژگی را توضیح ده و تایید انسانی بگیر.

چه ویژگی‌ای در بلاگ می‌خواهی پیاده‌سازی کنی؟ (مثلاً: ایجاد پست، ویرایش پست، لیست پست‌ها، حذف پست)
دولوپر: می‌خواهم امکان «ایجاد پست جدید در بلاگ» را بسازم. کاربر عنوان، متن و تصویر کاور را وارد می‌کند و پست ذخیره می‌شود.
سامانه: برای این ویژگی، مراحل زیر پیشنهادم است:
  1. Architect: طراحی مدل داده و API (جدول posts در PostgreSQL، مسیر POST /api/posts)
  2. Implementer: کدنویسی Route، سرویس، و اعتبارسنجی ورودی
  3. Reviewer: بررسی کد، تست و Security
  4. Fix loop در صورت لزوم
  5. Deliver: به‌روزرسانی CHANGELOG و README
آیا این برنامه را تایید می‌کنی؟
دولوپر: بله، تایید می‌کنم. ادامه بده.
مرحله ۴: معماری و نوشتار قرارداد (Architect)
سامانه (معمار): سلام. من معمار این ویژگی هستم. بر اساس نیاز، ساختار زیر را پیشنهاد می‌دهم:
مبناتصمیم
مدل دادهجدول posts با فیلدهای: id (UUID, PK), title (varchar), content (text), cover_image_url (text), created_at, updated_at
APIمسیر POST /api/posts با بدنه JSON شامل title, content, cover_image_url
اعتبارسنجیعنوان الزامی است و حداکثر ۲۰۰ کاراکتر؛ متن الزامی است
سرورNext.js API Route در پوشه app/api/posts/route.ts
احراز هویتنیاز به middleware احراز هویت قبل از ایجاد پست

بخش Contract (قرارداد تکنولوژیک)

فایل قرارداد در مسیر docs/contracts/create-post.md ایجاد می‌شود. محتوای پیشنهادی:

  • Endpoint: POST /api/posts
  • بدنه درخواست: { title: string, content: string, cover_image_url: string }
  • پاسخ موفقیت: 201 Created با { id: uuid }
  • پاسخ خطا: 400 اگر عنوان خالی باشد؛ 401 اگر احراز هویت نشده باشد
  • سیستم فایل: یک رکورد در جدول posts درج می‌شود
سامانه: معیارهای پذیرش (Acceptance Criteria) با دستور verify:
#معیار پذیرشدستور verify
AC-1title خالی پاسخ 400 می‌دهدnpm test -- --grep "empty-title"
AC-2بدون احراز هویت پاسخ 401 می‌دهدnpm test -- --grep "unauth-post"
AC-3با داده‌های معتبر پاسخ 201 و رکورد در دیتابیس می‌دهدnpm test -- --grep "valid-post"
آیا این طراحی، بخش Contract و معیارهای پذیرش را تایید می‌کنی یا تغییری می‌خواهی دهی؟
دولوپر: طراحی و контракт خوب است. معیارهای پذیرش هم دقیق هستند. تایید می‌کنم.
مرحله ۵: اجرا و ایجاد فایل قرارداد (Implementer)
سامانه (اجراکننده): سلام. من اجراکننده هستم. کدهای ویژگی «ایجاد پست» را نوشتم.

اقدامات انجام شده:
  1. فایل docs/contracts/create-post.md را بر اساس بخش Contract معمار ایجاد کردم
  2. فایل app/api/posts/route.ts را نوشتم با middleware احراز هویت و اعتبارسنجی
  3. دستور npm test را اجرا کردم → ۴ تست از ۵ موفق؛ یک تست مربوط به «تصویر کاور الزامی» شکست خورد
  4. دستور npm run lint را اجرا کردم → ۳ هشدار در مورد متغیر استفاده‌نشده
  5. دستورهای verify معیارهای پذیرش را اجرا کردم → AC-1 و AC-2 موفق، AC-3 شکست خورد (چون تست مرتبط نوشته نشده بود)


می‌خواهی اینها را قبل از بررسی Reviewer اصلاح کنم، یا مستقیماً ارسال کنم؟
دولوپر: اصلاح کن. لطفاً تست failures، هشدارهای لینتر و AC-3 را برطرف کن.
سامانه: اصلاح شد. دوباره اجرا می‌کنم:
npm test → ۵ از ۵ موفق.
npm run lint → بدون هشدار.
npx tsc --noEmit → بدون خطا.
دستورهای verify معیارهای پذیرش → AC-1، AC-2، AC-3 همه موفق.

حالا ویژگی آماده برای بررسی Reviewer است. ارسال می‌کنم؟
دولوپر: بله، ارسال کن.
مرحله ۶: بررسی با فایل قرارداد و معیارهای پذیرش (Reviewer)
سامانه (بازبینی‌گر): سلام. من بازبینی‌گر هستم. کد، فایل قرارداد و معیارهای پذیرش ویژگی «ایجاد پست» را بررسی کردم. یافتهای من:

  • کد را با فایل قرارداد docs/contracts/create-post.md مقایسه کردم — هیچ انحرافی مشاهده نشد.
  • تمام دستورهای verify: در معیارهای پذیرش اجرا شدند و خروجی صفر دادند (هیچ نقضzy از قرارداد مشاهده نشد).
  • تست‌ها برای هر معیار پذیرش وجود دارند و جدی asserting می‌کنند (تست‌های معیار پذیرش وجود دارند و تایید می‌کنند..
  • راز جدیدی اضافه نشده است (راز جدیدی اضافه نشده است).
آیا می‌خواهی Findings را اصلاح کنی؟
دولوپر: بله. هر دو CRITICAL و HIGH را اصلاح می‌کنم. INFO را هم می‌پذیریم و نام فایل را تغییر می‌دهیم.
مرحله ۷: حلقه اصلاح (Fix Loop)
سامانه (اجراکننده): middleware احراز هویت به endpoint اضافه شد. پیام خطا برای title خالی به «عنوان پست نمی‌تواند خالی باشد» تغییر کرد. نام فایل به create.route.ts تغییر یافت.

npm run lint → بدون هشدار.
دستورهای verify معیارهای پذیرش → AC-1، AC-2، AC-3 همه موفق.

ارسال دوباره به Reviewer؟
دولوپر: بله.
سامانه (بازبینی‌گر): بررسی دوباره انجام شد. CRITICAL به صفر رسید. HIGH اصلاح شد. INFO پذیرفته شد. تایید نهایی می‌دهم.
مرحله ۸: تحویل و cierre (Deliverer)
سامانه (تحویل‌دهنده): سلام. من تحویل‌دهنده هستم. ویژگی «ایجاد پست» با موفقیت تایید شد. حالا لطفاً:

جمع‌بندی سناریو

دولوپر در این سناریو هیچ کد پروژه را ننوشتد؛ فقط به سوالات سامانه پاسخ داد:

  • Stack و زبان پروژه (پر کردن Placeholderها)
  • دستور تست، لینتر، typecheck و build
  • تایید برنامه اورکستراتور
  • تایید طراحی معمار، بخش Contract و معیارهای پذیرش
  • تایید ایجاد فایل قرارداد docs/contracts/create-post.md
  • اصلاح خطاهای تست، لینتر و دستورهای verify
  • اصلاح Findings CRITICAL و HIGH Reviewer
  • تایید نهایی و به‌روزرسانی مستندات، ولاگ و last_verified
این سناریو نشان می‌دهد چگونه mr-opencode به عنوان یک «واibcoder کامل» برای توسعه محصول بدون نیاز به نوشتن دستی کدهای پیاده‌سازی توسط دولوپر عمل می‌کند. فایل قرارداد و معیارهای پذیرش (ATP) از بخش معماری تا بررسی و تحویل، جزء'abbaye ورک‌فلو هستند.
