## خلاصه مدیریتی برای ارائه به هیئت مدیره

### این چیست؟

یک **قالب پروژه (Project Template)** برای OpenCode است که یک جریان کاری کامل توسعه نرم‌افزار را به صورت خودکار و کنترل‌شده پیاده‌سازی می‌کند. به زبان ساده: یک «کارخانه نرم‌افزار» که از ایده تا تحویل، با کمترین دخالت دستی و بیشترین کنترل کیفیت کار می‌کند.

این قالب **مستقل از پشته فناوری** طراحی شده است. هیچ فرضی درباره زبان برنامه‌نویسی، فریم‌ورک، پایگاه داده یا ابزار تست ندارد. هر پروژه جدیدی می‌تواند آن را کپی کند و با پر کردن چند جای‌خالی (Placeholder)، آماده استفاده شود.

### چه مشکلی را حل می‌کند؟

**مشکل فعلی توسعه با ابزارهای هوش مصنوعی:**

- توسعه‌دهنده باید مدام به AI دستور بدهد، خروجی را کپی کند، به مرحله بعد ببرد
- AI ممکن است کد ناامن بنویسد، رمز لو بدهد، یا تست را نادیده بگیرد
- هیچ حافظه سازمانی وجود ندارد؛ هر Session از صفر شروع می‌شود
- کیفیت خروجی به مهارت و حوصله توسعه‌دهنده در نوشتن Prompt بستگی دارد
- بررسی کد (Review) اغلب فراموش می‌شود یا سطحی انجام می‌شود

**راه‌حل این قالب:**

- یک **زنجیره خودکار** از Agentهای تخصصی که هر کدام نقش مشخصی دارند
- **قواعد سخت** که AI نمی‌تواند از آن‌ها عبور کند (ممنوعیت push، ممنوعیت خواندن رمز، ممنوعیت ویرایش فایل‌های محافظ)
- **حافظه سازمانی** که تصمیمات و رفتار محصول را ثبت می‌کند
- **حلقه بازخورد خودکار** که خطاها را قبل از رسیدن به انسان شناسایی می‌کند

### چطور کار می‌کند؟ (جریان کاری)

```
ایده → Architect (طراحی + معیارهای پذیرش) → تأیید انسان
     → Implementer (کدنویسی + تست + خوداصلاحی)
     → Reviewer (بررسی مستقل با مدل متفاوت)
     → Implementer (رفع ایرادات)
     → مستندسازی رفتار → تحویل
```

**نکته کلیدی:** انسان فقط در دو نقطه تصمیم می‌گیرد: تأیید طرح اولیه، و تأیید نهایی تحویل. بقیه مسیر خودکار است.

### چه ارزشی برای سازمان ایجاد می‌کند؟

| ارزش                     | توضیح                                                                                                                                   |
| :----------------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |
| **کاهش بار توسعه‌دهنده** | توسعه‌دهنده به جای «هدایت مدام AI»، فقط طرح را تأیید می‌کند و نتیجه را بررسی می‌کند. عملیات مکانیکی (تست، بررسی، مستندسازی) خودکار است. |
| **کیفیت قابل پیش‌بینی**  | قواعد سخت (ممنوعیت `any`، الزام تست، الزام بررسی) تضمین می‌کند خروجی حداقل استاندارد را رعایت کند، مستقل از مهارت توسعه‌دهنده.          |
| **امنیت**                | سه لایه دفاعی: ممنوعیت خواندن `.env`، مسدودسازی الگوهای رمز در Plugin، و اسکن pre-commit. AI نمی‌تواند رمز را در کد بنویسد یا بخواند.   |
| **حافظه سازمانی**        | هر ویژگی یک «سند رفتار» تولید می‌کند که در Sessionهای بعدی به عنوان زمینه استفاده می‌شود. دانش محصول از دست نمی‌رود.                    |
| **مقیاس‌پذیری**          | یک قالب برای همه پروژه‌ها. پروژه جدید = کپی قالب + پر کردن چند جای‌خالی. بدون نیاز به بازآموزی تیم.                                     |
| **شفافیت**               | هر تصمیم در فایل plan ثبت می‌شود. هر بررسی در فایل review. قابل ردیابی و حسابرسی.                                                       |

### چه چیزی در آن هست؟ (اجزای کلیدی)

| لایه          | محتوا                                                           | نقش                                                |
| :------------ | :-------------------------------------------------------------- | :------------------------------------------------- |
| **پیکربندی**  | `opencode.jsonc`، `AGENTS.md`                                   | حاکمیت، استانداردها، مدل مجوزها                    |
| **Agentها**   | Architect، Implementer، Reviewer، TestRunner                    | تفکیک نقش، مدل، و سطح دسترسی                       |
| **Skillها**   | mro-project-stack، mro-data-model، mro-behavior-docs، mro-code-review-checklist | دانش on-demand (فقط وقتی لازم است بارگذاری می‌شود) |
| **Commandها** | `/mro-plan-feature`، `/mro-run-review`، `/mro-fix-tests`، `/mro-debug`، `/mro-deliver`        | نقاط ورود یکپارچه برای توسعه‌دهنده                 |
| **Pluginها**  | mro-protect-secrets، mro-test-feedback، mro-project-tools                   | دفاع امنیتی، بازخورد خودکار، ابزارهای سفارشی       |
| **حافظه**     | `plans/`، `reviews/`، `docs/behaviors/`                         | ثبت تصمیمات، بررسی‌ها، و رفتار محصول               |

### چه چیزی در آن نیست؟ (مرزهای آگاهانه)

- **CI/CD و GitHub Actions:** عمداً حذف شده. این قالب برای توسعه محصول است، نه استقرار.
- **MCP Serverها:** عمداً خالی. هر MCP اضافی Context را اشغال می‌کند و کیفیت را کاهش می‌دهد.
- **پشته فناوری مشخص:** عمداً مستقل. هر پروژه آن را پر می‌کند.
- **جستجوی وب:** تا زمانی که Provider تنظیم نشود، خاموش است.

### تفاوت با Cursor

| ویژگی      | Cursor                | این قالب                                        |
| :--------- | :-------------------- | :---------------------------------------------- |
| خودکارسازی | Background Agent ابری | Agentهای محلی با پروتکل Handoff                 |
| کنترل      | کمتر (اتکا به مدل)    | بیشتر (قواعد سخت + Permission)                  |
| حافظه      | محدود به Session      | plans + reviews + behavior docs                 |
| امنیت      | عمومی                 | سه لایه دفاعی اختصاصی                           |
| هزینه      | اشتراک ثابت           | قابل بهینه‌سازی (مدل‌های ارزان برای وظایف ساده) |

**نتیجه:** این قالب «Cursor با ترمز» است. همان راحتی، اما با کنترل و امنیت بیشتر برای محیط‌های سازمانی.

### وضعیت فعلی و گام بعدی

**وضعیت:** قالب ساخته شده و آماده استفاده است. برای هر پروژه جدید:

1. کپی قالب به پروژه
2. `git init` و فعال‌سازی pre-commit hook
3. پر کردن ۱۲ جای‌خالی (پشته، دستور تست، مدل و غیره)
4. اجرای `opencode debug config` برای تأیید

**گام بعدی پیشنهادی:** اجرای یک پایلوت روی یک پروژه واقعی (مثلاً یک ویژگی کوچک) و اندازه‌گیری:

- زمان صرف‌شده توسط توسعه‌دهنده در مقایسه با روش دستی
- تعداد ایرادات کشف‌شده توسط Reviewer قبل از تحویل
- رضایت توسعه‌دهنده از تجربه کاربری

### یک جمله برای هیئت مدیره

> «ما یک کارخانه نرم‌افزار خودکار ساخته‌ایم که توسعه‌دهنده را از عملیات مکانیکی آزاد می‌کند، کیفیت و امنیت را با قواعد سخت تضمین می‌کند، و دانش محصول را در سازمان حفظ می‌کند — بدون وابستگی به پشته فناوری خاص یا ابزار ابری.»
